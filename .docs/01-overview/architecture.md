# Architecture

> **TL;DR** Each lab is one WinForms form with all logic in its button click handlers.
> floormat: `frmMatsRUs` computes price = grade constant + surcharges, then 6% tax.
> marks: `Form1` gates five `TryParse` results, then sums and bands the total. The
> `.Designer.vb` files are generated — control names there must match `Handles` clauses.

## Common shape

Both projects follow the classic VB.NET WinForms lab pattern:

- `Form1.vb` — hand-written code-behind: event handlers + helper functions. This is the only
  file with real logic.
- `Form1.Designer.vb` — generated by the Visual Studio designer: control declarations and
  layout (`InitializeComponent`). Edit via careful hand-sync or a designer, never casually.
- `Form1.resx` — designer resources for the form.
- `My Project/` — assembly info and generated application scaffolding (`Application.myapp`
  boots the form as the startup object).
- `App.config` — supported-runtime declaration (.NET Framework 4.7.2).

No classes beyond the form, no data layer, no persistence — state lives in the controls.

## floormat — `LabAssgQ1` / `frmMatsRUs`

Pricing constants are form-level `Const` fields: `dblStandard = 99`, `dblDeluxe = 129`,
`dblPremium = 179`; colours `dblBlack = 0`, `dblBlue = 5`, `dblOther = 10`.

`btnCalculate_Click` flow:

1. Grade radio (`radStandard` / `radDeluxe` / `radPremium`) selects the base price.
2. Colour radio (`radBlack` / `radBlue` / `radOther`) selects the surcharge; the
   `chkFoldable` checkbox adds 25 to it.
3. `CalculatePrice(price, addPrice)` returns the subtotal; `CalculateAdditionalPrice(subtotal)`
   returns 6% tax (`* 0.06`).
4. Results land in `lblSubTotal` / `lblSalesTax` / `lblTotalDue` via `.ToString("c")`
   (currency format).

Validation (fixed): clicking Calculate with **no grade radio checked** used to leave
`dblPrice` at 0 and price tax on the surcharges alone. The handler now returns early with a
"Please select a mat grade (Standard, Deluxe or Premium) first." prompt before any pricing.

## marks — `LabAssg1Q2` / `Form1`

`cmdCalculateMark_Click` flow:

1. Five `TryParse` calls: `Integer.TryParse(txtStudentNumber...)` plus `Double.TryParse` on
   `txtExamination`, `txtGroupProject`, `txtTest`, `txtQuiz` — each returning a `bln*` flag.
2. All five flags must be true (`blnStudent And blnExam And ...`); otherwise a
   "Please input data correctly" warning `MsgBox` and nothing is computed.
3. Range gate: each mark must fall within its weight (exam 0–50, GP 0–25, test 0–15,
   quiz 0–10); the first violation shows a "Mark Out Of Range" `MsgBox` and returns.
4. Valid path: total = exam + GP + test + quiz; `Select Case` bands the grade
   (>= 85 A, >= 75 B, >= 65 C, >= 55 D, else E); results go to `lblTotalMarks` / `lblGrade`
   and a summary `MsgBox` (student number, name, grade).

`btnClear_Click` empties every textbox and result label; `btnExit_Click` closes the form
(both labs).

Validation (fixed): each component mark is now range-checked against its own weight —
Examination 0–50, Group Project 0–25, Test 0–15, Quiz 0–10 (the percentages printed on the
form labels). The old `60 + 60 + 60 + 60 = 240` earning an "A" is rejected with a specific
"Mark Out Of Range" message naming the offending field; nothing is computed or displayed.

## Build pipeline

`justfile` → MSBuild (`/p:Configuration=Debug`) → `bin\Debug\{Project}.exe` per lab. MSBuild
resolves via two paths: VS Build Tools MSBuild if installed, else the Framework MSBuild at
`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\MSBuild.exe` (3 benign warnings — see
[../06-troubleshooting/common-issues.md](../06-troubleshooting/common-issues.md)).
