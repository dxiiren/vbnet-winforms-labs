# FAQ

> **TL;DR** Quick answers: why two apps in one repo (same course, same stack, tiny), why the
> typo in a solution filename (archive fidelity), why no tests/CI (preserved coursework),
> why the build warns (Framework MSBuild), and why known logic quirks aren't "fixed".

## Why are two separate solutions in one repo?

They are Question 1 and Question 2 of the same university VB.NET lab assignment (2022) —
same stack, same era, each only a single form. Bundling them keeps the portfolio tidy; the
justfile's `lab` parameter keeps them independently buildable and runnable.

## Why is "Assesment Mark Program.sln" misspelled?

That is the filename as submitted in 2022. The import preserves archive names (only the
parent folders were renamed — see the mapping in
[../01-overview/project-overview.md](../01-overview/project-overview.md)). Renaming the
`.sln` would rewrite history the repo exists to preserve.

## Why does every build print warnings?

You're on the Framework MSBuild that ships with Windows — its 3 warning classes are
documented and benign ([../06-troubleshooting/common-issues.md](../06-troubleshooting/common-issues.md)).
Installing VS Build Tools 2022 (manual, optional) makes builds warning-free.

## Why no tests, linter, or CI?

Preserved coursework, kept as submitted. Verification is the build + launch smoke
(`just build-all`, `just run {lab}`), scripted in the `/lint-check` skill. Adding test
infrastructure to a 60-line lab would be scaffolding for its own sake.

## The floormat app prices RM0 with no grade selected / the marks app accepts 240 marks. Bug?

Known quirks of the original submissions, documented in
[../01-overview/architecture.md](../01-overview/architecture.md) and deliberately left
in place — the repo preserves the coursework as graded. Fix them only as an explicit,
separately-committed enhancement, never silently.

## Can I open these in Visual Studio instead of using just?

Yes — each `.sln` opens in any VS with .NET desktop workload; the `.vs/` cache it creates
is git-ignored. The justfile exists so the repo works without VS installed.

## Where did the original bin/obj output from the archive go?

Deliberately not imported (and git-ignored): build output is regenerated by `just build`,
and the archive's stale `obj/` caches would have caused MSB3088 warnings.
